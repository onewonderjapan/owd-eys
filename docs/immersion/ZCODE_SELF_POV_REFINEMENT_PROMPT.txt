F1：建立可信的身体与眼位关系（R1、R3）

F2：修正水下链石的真实连接与低头构图（R2）
- 当前上锚点 X 写死 sinkX，而玩家初段 X=0。把上端绑定到身体实际局部绑点，下端绑定导出 GLB 的 chain_anchor，updateWorldMatrix 后获取世界坐标。抬起、抛出、水下三个阶段都不能脱节。
- 28 个实例链节的尺寸和节距要匹配真实链长；避免挤成黑色团块。复用 InstancedMesh，每帧更新矩阵，不每帧创建几何/材质。
- 当前眼位几乎在链石正上方，近端遮住远端。调整身前绑点、石块相对前方的少量偏置、链节粗细和弱轮廓光，使低头约 60–75° 即能读到“身体下缘 → 一段长链 → 下方独立灰石”。不需要强迫用户转到极限角度，不用放大石块贴脚，不改成 NPC 旁观镜头。
- 保持深蓝留白、石块低于鹅、整体慢沉；用户参考 <workspace>/reference_research\immersion_20260913\user-water-sinking.jpg 不显示海床，不增加撞底场面。
- 修复现有诊断的同值比较：真实模型上下锚点与实际首末链节端点分别测量，不可由同一个数组互相赋值后宣称误差为零。仅针对该不变量补必要检查，覆盖抬起/抛出/水下各一时刻；沿用 ≤0.03 项目单位容差，解释端点定义。

F3：让托举、抛出、投入火堆成为连续动作（R3）
- 两只陪同鹅用现有翼部 pivot 做“接近/托住 → 抬起 → 松开”的简短动作；接触在自己 POV 左右下缘能被看见，抬起时相对位置可信。不要两只鹅一直 standing 后让玩家自行平移。无须刚体、布娃娃或新骨骼系统。
- 水/火各自轨迹共享身体/眼位规则；阶段边界的位置和朝向连续，速度合理衔接。尤其修掉火堆 1.2s 偏置变化、2.2s 直接跳 pitEye 的问题。
- 火堆：开始能看到坑和火；抬举/短抛物线中目标逐渐靠近并进入下方/四周；落定时火根、坑沿或木柴仍提供位置参照。不能跳成空地+红翅膀，不能靠颜色变化冒充被投入。
- 主动转头时允许用户看别处；验收“目标不丢”针对默认观察轨迹，不能用强制锁头换取构图。

F4：水面事件、水色和轻量效果（R4、R5）
- 区分身体碰水和眼位穿过水面的事件，依同一条轨迹驱动对应水花/水下声音和环境。消除当前 2.4s 已触发水下效果但眼位还在水面上的错位，以及两次整片闪白。
- 深水前视也应是深海军蓝、上方弱亮下方暗，保留可读的链石轮廓。背景、稀疏气泡、中远处鱼群提供相对运动，让慢沉看得出来。核心水下可观察时长至少约 3 秒；若需微调总时长，集中在 immersion-config.js 并记录理由，不散落硬编码。
- 保留鱼群，去掉“纯圆锥当鱼”：使用共享的低面数鱼身+尾鳍轮廓、柔和颜色，控制离相机距离，避免巨大尖锥冲到脸前。气泡用小而柔的透明轮廓，不能看成灰色实心碎石，不遮链石。
