## 1. 官方机制(参考边界)

官方 v1.03 补丁说明:会议投票平票时,被投者**入狱而非出局**——被押入 Goosechapel 牢房,
狱门落锁;下一轮开始时两把钥匙自动开锁释放。平票不是死亡,角色保留继续游戏资格。
官方截图/补丁文本仅作机制与画面参考,不进入 src/ 与生产资产;触发条件为本项目改编。

## 3. 局外状态影响面(工作量 M-L 的根源,实现前逐项确认)

1. **状态机**:`immersion-state.js` 的会话快照需增加 `jailedActorId`(或列表)字段;
   replay/重播语义要定义(入狱者的重播 = 牢门关闭而非 ejection 舞台)。
2. **保护规则**:关押期间该角色**不可被演出处决**——若下一轮会议再次平票涉及同一角色,
   需定义(官方:继续关押?我们建议:保持关押、本轮平票改为无人出局)。
3. **会议流程**:discussion/voting 阶段台词池需能提及"某人在牢里";被关押者不参与投票
   (官方如此)还是照常投票(**建议照常投票**,避免削弱参与感——与官方差异记入 NOTICE)。
4. ** muzzle 风格选择器**:入狱分支不走 style-picker;自演示(自我被投出)平票时是否
   允许体验入狱 POV——建议允许(复用 busy 舞台机制)。
5. **释放时点**:"一局后自动放出"需要跨会话记忆。当前 director 是单会话生命周期,
   无跨会话状态——需在 map-walk 层持有一个 `pendingRelease` 标记,下一次会议开始时消费。
   这是唯一真正的新基础设施;其余都是现有状态机的分支。
6. **冒烟与发布门**:smoke 需要平票固化管理(state机已可确定性造平票;roster 27 人)。

## 4. 验收草案

- 平票 → 入狱 POV(牢门关闭)→ 名册"入狱"徽章;桌面 + MOBILE 全绿。
- 下一轮会议开始:两把钥匙动画 + 释放;释放后可正常被投票/演出。
- 关押期间任何 ejection 路径都不会作用于被关押者(专项断言)。
- reduced-motion:牢门关闭动画可关(直接切换 + 横幅说明)。
